# Ежедневное обновление цен

Этот проект умеет брать обычный текстовый прайс поставщика, применять правила наценки и подставлять цены только в те товары, которые уже есть в каталоге.

Если точного совпадения нет, на сайте останется `цена по запросу`.

## Как обновлять цены

1. В папке проекта создайте файл `supplier-prices.txt`.
2. Вставьте туда свежий текст поставщика.
3. Запустите команду:

```powershell
npm.cmd run prices:update
```

Правила уже зашиты в скрипт:

- AirPods: `+2 000 ₽`;
- iPad: `+3 000 ₽`;
- вся линейка iPhone 16: `+3 500 ₽`;
- вся линейка iPhone 17 и iPhone Air: `+4 000 ₽`.

После наценки цена округляется вверх: хвост `100-400` до ближайших `500`, хвост `600-900` до ближайшей `1 000`. Цены с хвостом `000` или `500` не меняются.

Если в строке поставщика не указан тип SIM, скрипт считает её версией `Nano-SIM + eSIM`.

4. Скрипт обновит файл:

```text
app/data/price-overrides.json
```

5. После проверки отправьте обновление на GitHub:

```powershell
git add app/data/price-overrides.json
git commit -m "Update catalog prices"
git push
```

Vercel сам обновит сайт и Telegram Mini App после пуша.

## Как скрипт понимает прайс

Пример строки:

```text
17 Pro Max 512 Orange 1Sim - 119.000
```

Скрипт распознает:

- модель: `iPhone 17 Pro Max`;
- память: `512GB`;
- цвет: `Cosmic Orange`;
- SIM: `Nano-SIM + eSIM`;
- закупочную цену: `119 000 ₽`.

Для строки выше получится: `119 000 ₽ + 4 000 ₽ = 123 000 ₽`. Округление не изменит цену, и на сайте будет показано `123 000 ₽`.

## Что игнорируется

- модели, которых нет в каталоге;
- цвета, памяти или SIM-версии, которых нет в карточке товара;
- строки `Актив` / `Asis`, потому что это отдельное состояние товара;
- строки, где невозможно понять модель, цвет, память, SIM или цену.

Сырые прайсы поставщика не коммитятся: файл `supplier-prices.txt` добавлен в `.gitignore`.
